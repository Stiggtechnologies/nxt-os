# Native workpaper data mining

Reports opens a read-only designer for saved NXT preparation workpapers. Choose program, years, jurisdiction, statuses, name/reference, catalog columns and up to eight typed conditions. The selected company and the caller's staff assignments both restrict the records. Original migrated DT Max records remain in the source workspace and its existing verified exports; this designer does not reinterpret them.

The report always includes workpaper ID, program, year, jurisdiction, revision and saved-calculation state. Catalog fields carry scalar types. Money remains integer cents in the API; missing values stay null. Default calculation columns include amounts only when the saved input document, current input hash/revision, saved output hash and current program/year/jurisdiction scope agree and the saved result was supported. Historical, unsupported, blocked and stale results require the explicit historical option; they keep their state.

`GET /api/tax/reports/catalog` lists the available scalar fields. `POST /api/tax/reports/preview` accepts JSON filters and reads one immutable in-memory view of the saved tax state. It does not calculate, edit, approve or file a workpaper. Authorization/MFA still applies. This exact POST is treated as a read by staff role policy, so assigned read-only/front-desk users can prepare a report without receiving write access. Every record is filtered by verified identity before filtering, count or fingerprint calculation. An explicit unauthorized client filter returns403.

Reports are complete or fail: at most10,000 rows and3MiB,48 selected columns plus the required provenance columns. No partial file is offered when a limit or invalid scalar is encountered. The first200 rows are shown in the preview; CSV uses the whole verified response. A snapshot SHA256 commits to normalized request, columns and rows. Export repeats the request and compares the snapshot with the displayed preview. Changed records require another review of the refreshed preview. Changes to filters/company, navigation or cancellation reject a pending response.

CSV is UTF-8 with a BOM, quoted fields and CRLF records. Money headers end in `_CAD`; values are exact decimal text. Every data cell has one additional protective apostrophe, including numeric values. Parse CSV and remove exactly one to recover literal values. Null becomes an empty field, never zero. The report-kind/snapshot/financial-approval columns retain export qualification. This is a report format, separate from the native workpaper import package.

Save report setup downloads only the selected filters/columns as versioned JSON. Load validates the whole setup against the catalog and selected company before altering controls; it does not execute a query or create a workpaper. Saved setups may contain a typed name/reference filter and should be handled as office data.

Validation covers scoped projection/fingerprints, authenticated HTTP with real synthetic staff/MFA roles, unchanged native records, typed comparisons, blank versus zero, stale/unsupported snapshots, bounded output, exact money/CSV encoding and normal browser preview/export/setup/cancel/company-change controls. It does not establish complete historical tax calculations, official forms or filing certification.
