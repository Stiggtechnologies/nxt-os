# Additional original source archives

This finite third archive profile preserves six original PDF byte streams and22 source-client/year associations. Four General packets contain20 verified identification pages; two T5007 packets contain two verified slip pages with copies2 and3 kept separately. The original131-association and22-association profiles and their API responses are unchanged.

Only each listed page establishes a client/year link. One original contains two clients and is explicitly marked as a mixed-client packet. AMENDED2018 stamps are retained separately from the official2015/2016 tax-year banners. The2011/2012 General links and2007/2008 T5007 links have no same-year native contexts. Those years become source-archive links only; no native return is invented.

The source qualification preserves six nonexact whole first-name cells: five contain a separate courtesy title, and one has a spelling variation. Exact own-taxpayer SIN, labeled birth date and visible client reference bind the General pages to original CRC-verified Info1 records. The spelling or title is never used to edit client profiles or claim current legal identity. T5007 recipient name and SIN establish source continuity to available native years; DOB is not printed or inferred.

T5007 observations are preserved as exact JSON strings with a separate SHA256 and full descriptor pin. Each physical copy retains its Box10 printed literal and integer cents. Box11 remains blank/null, never zero. Structured metadata contains only a masked SIN. The original private PDF remains unchanged. These copies are not summed, normalized as slips, mapped to T1 lines144/250, assigned to current cases or approved as financial values.

## API and storage

The existing authenticated `identification-source-archives/chunks` and `/commit` methods accept the new finite profile. The additive GET `/identification-source-archives/mixed-profile` reports its client-free contract. The old `/profile` and `/additional-profile` responses are unchanged. Existing return-PDF metadata/list and archive-chunk read methods return the original bytes and exact per-association scope. Commit replay repairs both association indexes.

New optional scope fields are omitted when absent, preserving old serialized records: `known_mixed_client_packet`, `source_name_match`, `source_name_qualification`, `printed_slip_observations_json`, and `printed_slip_observations_sha256`. Only the new closed profile can carry these fields. Every complete descriptor is pinned; roles, owner, year, verified page, optional fields and observation bytes cannot be substituted.

The six originals total94,560,121 bytes,207 pages and93 one-MiB immutable chunks. The current transport stores lowercase hexadecimal, requiring189,120,242 payload characters plus key/index/metadata overhead. The production uploader must recheck capacity; this change does not alter storage configuration or billing.

## Source limits

No full-packet ownership, complete-return, native-generation, CRA-acceptance, as-filed or financial-approval claim is made. Other packet pages remain unassigned. No profiles, native histories, current tax cases, economic slips, original PDF metadata or earlier printed-figure observations are rewritten.
