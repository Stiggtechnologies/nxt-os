# Imported T1 client list CSV

In **T1 clients imported from DT Max**, apply Find client, imported year, processing status, province and sort/order filters. Choose **Export client list CSV** to download **all matching profiles**, including pages not currently visible. This is a read-only list-review export. It does not create or edit a source, current client, tax case, ownership link or financial value. It is separate from NXT's canonical migration-import CSV and must not be supplied to that importer.

The browser uses a separate authenticated effective SOURCE roster GET: `/api/source-imports/dtmax/companies/dtmax-test-copy/test-copy/recovered-native-sources/effective/source-clients/export`. It runs the same complete, filtered and sorted projection as the normal client list, including every native/paper/archive/recovered identity and year check, before pagination. The existing page and raw-source APIs keep their 100-row limits and unchanged responses. No source-facts reads or storage/cache writes are added. The export makes two sequential whole-payload GETs instead of 118 page GETs for 5,856 clients (three roster GETs including the initial list). Progress identifies the scan and row count; Cancel stops further reads. A request already in flight may finish, but its result cannot download after cancellation. The browser never silently falls back to a partial page or a different source API.

Both complete responses require the exact versioned scope/qualifier/filter envelope, a SHA-256 fingerprint of canonical JSON content, exact counts, at most 10,000 globally unique valid source client numbers, identical full rows/filter inventories, and an inclusive serialized response bound of 3 MiB. The server enforces the byte/count bounds before returning any export body; the browser independently checks them and the fingerprint before producing CSV. Oversized or changed records, permission failures or unsupported text stop the export with **no partial CSV**. Editing filters, submitting Find, changing list pages/views, leaving or disposing the workspace also invalidates the operation. Unapplied filter edits require Find before another export. The fingerprint identifies observed content, **not a database revision**: two matching full reads establish observed stability, **not an atomic database snapshot**. No source version is chosen automatically.

The filename is `dtmax-t1-source-client-list-review.csv`. It has a UTF-8 BOM, comma separators, a header row, quoted fields, escaped double quotes and CRLF record endings. Commas, quoted text, embedded CR/LF and Unicode are preserved. Every **data** cell starts with exactly one additional apostrophe. This explicit `leading_apostrophe_remove_exactly_one/v1` text encoding prevents formula-like text from starting a spreadsheet expression and protects leading-zero identifiers. To reconstruct the exact source cell, parse CSV syntax and remove **exactly one** leading apostrophe, including when the source itself begins with an apostrophe. Do not trim, normalize or convert identifiers to numbers. CSV has no native type system: spreadsheet applications may show the protective apostrophe; import columns as text rather than relying on automatic coercion. The file is for list review, not executable formulas or an import mapping.

The columns retain the SOURCE roster's client number and literal name, imported processing-status/province text, and each year array separately. Year-array cells contain JSON (for example `[2021,2024]`); an optional array absent from the API is `null`, while an explicitly empty array is `[]`. `historical_years` is the effective SOURCE navigation projection and may include verified recovered/paper source years. Native, paper, source-archive, recovered, pending and pending-at-import arrays retain their distinct meanings. These are source years, not assertions about a current tax return, filing or verified legal identity. Status/province blanks mean no source text supplied; they are not inferred defaults. The selected source-year/search/status/province filters, sort key/direction, source scope/program, encoding declaration and source-only qualification accompany each row. An empty result produces a header-only CSV after both scans.

No SIN, birth date, contact/address fields, figures, balances or tax totals are exported. Existing raw source packets, effective identity overlays, historical precision figures, PDF indexes and migration-import exports are unchanged.

This delivers the imported-list comma-delimited review function only. DT Max's own [client list export documentation](https://support.drtax.ca/dtmax/eng/kb/dtmax/dt%20max%20help%20directory/printing/printing%20client%20data/w847clst.htm) also describes printing, marked/family selections and destination-specific integrations; those are separate capabilities and are not claimed here.

Validation: `node --test tests/dtmax_client_list_csv.test.mjs` exercises the mounted component with synthetic 5,856-row and filtered multipage rosters, CSV byte/text roundtrips, empty results, malformed/drifting responses, permission failure, progress, cancellation, navigation and disposal. No private client fixtures, network access or source writes are required.

The JSON route uses normal firm-wide authorization, private/no-store responses and no new persistence. Authenticated route/filter/unknown-query/missing-profile tests run under `cargo test --locked` through `tests/dtmax_client_list_export.rs`. Library tests prove the exact 3 MiB boundary, unique/count holds and complete 5,856-row equality with the old paginated projection, with each profile read only once per export projection. Browser tests also compare the fast and paginated CSV bytes. Private offline acceptance reconstructs the accepted 3,088,065-byte live CSV exactly from the complete 1,559,802-byte actual-like DTO. These are local size/parity measurements; live optimization timing remains a separate release check.
