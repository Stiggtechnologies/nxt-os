# Readable earlier T4 source revision

A protected PDF retains a complete, populated earlier revision before its encrypted update. This release admits only that exact 340,070-byte prefix, one page containing two physical copies. The latest encrypted version remains locked. The viewer labels it as an earlier readable T4 revision and preserves the original prefix bytes for download.

The source association uses a unique own taxpayer identifier across the original 32,744 source contexts, exact surname and first name, and the printed middle initial. Three original 2023–2025 Info1 records were freshly expanded and checked against their source frames, context boundaries, lengths, CRC and hashes. The current source profile remains unchanged. A birth date is not printed on this slip and is not inferred from it.

Each physical copy retains fifteen monetary cells, including two cells with only `00` printed in the cents position. Blank cells remain null. The two copies are not summed or counted as additional economic slips. No native slip, current tax case, preferred figure, T1 line, filing status or financial approval is created.

The existing authenticated source-archive chunk/commit transport accepts one new finite profile. `identification-source-archives/prior-revision-profile` exposes only its client-free contract. The three earlier profiles and their responses remain unchanged. Owner, year, source byte range, recovery qualification, observation JSON and every immutable byte are bound by the closed profile and descriptor hashes. No encrypted original or previous metadata is rewritten.

Private source PDFs, identifiers, observations, import manifests and original witnesses remain outside Git. Local full-fixture validation uses `NXT_DTMAX_PRIOR_T4_MANIFEST`; the public profile and tests contain hashes only. Production acceptance requires a fresh profile/capacity check, immutable readback, prior controls/profile preservation and actual viewer/download verification.
